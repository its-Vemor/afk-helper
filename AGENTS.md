# AGENTS.md — Инструкции для разработчиков и AI-агентов

Добро пожаловать в репозиторий **afk-helper**! Этот файл содержит ключевую информацию об архитектуре, правилах разработки и стеке проекта.

## 🛠 Технологический стек
- **Язык**: Kotlin 2.3
- **Фреймворк**: Spring Boot 4.1.0
- **Доступ к данным**: Spring Data JDBC
- **Миграции БД**: Liquibase
- **База данных**: PostgreSQL
- **Сборка**: Gradle (Kotlin DSL)
- **Тестирование**: JUnit 5, Spring Boot Test

---

## 🏗 Архитектура и основные компоненты

1. **Управление аккаунтами (`accounts`)**:
   - Хранение идентификаторов и долгосрочных не экспайрящихся кодов авторизации (`auth_code`).
2. **Промокоды (`redemption_codes`)**:
   - Хранение кодов возмещения AFK Arena.
3. **Автоматическое применение**:
   - При добавлении нового кода в систему он автоматически применяется ко всем известным аккаунтам.
4. **Многоканальность (REST & Telegram Bot)**:
   - Бизнес-логика вынесена в сервисный слой. REST API и будущий Telegram-бот используют единые сервисы.

---

## 📁 Структура проекта
- `src/main/kotlin/ru/vemor/afkhelper/` — исходный код
  - `controller/` — REST контроллеры
  - `service/` — бизнес-логика (активация кодов, управление аккаунтами)
  - `repository/` — Spring Data JDBC репозитории
  - `model/` / `domain/` — доменные сущности и DTO
- `src/main/resources/db/changelog/` — миграции Liquibase
- `src/test/kotlin/ru/vemor/afkhelper/` — тесты

---

## 🚀 Команды для сборки и запуска
- Сборка проекта: `./gradlew build`
- Запуск приложения: `./gradlew bootRun`
- Запуск тестов: `./gradlew test`

---

## 📌 Правила и конвенции кодирования
- Строго соблюдайте идиоматичный Kotlin (null-safety, data classes, immutability где возможно).
- Все изменения схемы БД должны оформляться через Liquibase чейнджлоги.
- Покрывайте новую бизнес-логику unit- и интеграционными тестами.
